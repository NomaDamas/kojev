   123	## Root causes and the measurements behind them
   124	
   125	`/data2` is an NFS mount whose small-file creation rate was measured at
   126	2.6 files/sec (100 files in 38,765 ms), against 3,571 files/sec on tmpfs: a
   127	1,384x gap. Large sequential writes were healthy at 14.8 MB/s. The filesystem is
   128	therefore fine for data and hostile to environment builds, which is why the
   129	solution had to remove environment builds from jobs rather than speed them up.
   130	
   131	Fixes applied to the templates, each with a regression test:
   132	
   133	1. Shared `UV_CACHE_DIR` instead of a per-job cache directory. Job 13620 then
   134	   resolved 92 packages in 1 ms with zero downloads.
   135	2. `uv sync --no-dev`, cutting 29 downloads to 1. basedpyright alone ships
   136	   ~20k typeshed stub files and pulls nodejs-wheel-binaries, none of which the
   137	   cluster needs to train.
   138	3. `UV_LINK_MODE=hardlink` instead of copy, avoiding ~2 GB of duplication per job.
   139	4. Prefer a prebuilt shared venv; fall back to per-job sync only if absent.
   140	5. Launch the shared venv's interpreter directly rather than through `uv run`,
   141	   removing uv from the launch path entirely.
   142	6. Shift off the leading `--` that sbatch forwards as `$1`, so the plan's
   143	   documented `sbatch smoke.sbatch -- python -m kojev.train ...` works.
   144	
   145	## Self-inflicted incidents, recorded in full
   146	
   147	Two failures during this task were mine, not the cluster's.
   148	
   149	A stray `rm -rf .../uv-cache/.tmp*` whose glob was frozen at launch spent about
   150	90 minutes deleting the very staging the rebuild was creating. The signal was the
   151	file count moving backwards, 27,424 to 27,240: a build whose staging shrinks is
   152	not slow, it is losing a race. Killing it flipped the rate from -184 files/min to
   153	+162 files in 45 seconds.
   154	
   155	Job 13621 failed because the readiness check tested whether `torch/__init__.py`
   156	existed. uv writes a package progressively, so that file appears long before the
   157	package is complete. Worse, the payload did run an import probe, printed its
   158	traceback, and continued anyway because the output was piped through `head -2`
   159	and the exit status was never inspected. A probe whose result is discarded is not
   160	a check. Readiness now requires the installer to have exited AND
   161	`python -c "import torch"` to exit 0.
   162	
   163	Seven concurrent ssh monitors, several polling at 20-second intervals, also
   164	contributed to sshd refusing connections with `Exceeded MaxStartups`. Diagnosis
   165	came from a raw TCP probe reading that banner directly. Monitoring was rebuilt as
   166	a single loop making at most one attempt per 50-90 seconds.
