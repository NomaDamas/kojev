DEFECT (found by independent todo-8 verification, st_01a0c429)
Independent audit of the OOD set found 22 emitted OOD rows whose exact `state`
also appeared in GOLD train. GOLD val overlap was 0, and every OOD (source,state)
did originate in GOLD test - but the same raw state text existed in BOTH test and
train.

Root cause: _source_split_rows carves ROWS. Upstream Korean corpora (notably
e9t/nsmc) contain duplicate texts, so two rows carrying the same state string can
be assigned to different splits - identical rows hash to adjacent positions and a
slice boundary can cut between them. The gold corpus therefore leaked held-out
text into train, which would have contaminated todo 14's evaluation as well as
todo 8's OOD set.

Severity: blocking. Held-out integrity is a Must-have of this plan.

FIX (kojev/data_gold.py)
Added _enforce_split_state_isolation(), applied after all sources are mapped and
before any JSONL is written:
  - Iterates splits in priority order test -> val -> train.
  - A state string is kept only if no higher-priority split already claimed it.
  - Held-out splits win: test keeps everything it holds, val yields to test,
    train yields to both. Training data is sacrificed, never evaluation data.
  - Recomputes each source:split summary entry from the survivors and records
    `dropped_cross_split_state` so the loss is visible rather than silent.

REGRESSION TEST ADDED
  tests/test_data_gold.py::test_split_state_isolation_gives_held_out_splits_priority
    - Seeds the same state into all three splits.
    - Asserts the shared state survives ONLY in test.
    - Asserts all three pairwise split intersections are empty.
    - Asserts dropped_cross_split_state is 1 for train, 1 for val, 0 for test.
