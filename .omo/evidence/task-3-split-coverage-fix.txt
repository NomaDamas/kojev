DEFECT (found while implementing todo 8)
Plan todo 3 specifies:
  "Split: per-source shuffled seed 0, cap per source train<=8000 / val<=500 /
   test<=1000 STATES; test set shuffled across sources."
The landed implementation derived the kojev split from the upstream Hugging Face
split NAME (train / validation / test). Only e9t/nsmc ships an upstream "test"
split, so data/gold/test.jsonl contained exactly ONE source and 11 of 12 sources
never contributed any test state.

Impact:
  - Violates todo 3's own written split specification.
  - Blocked todo 8, which must build a rule-gold OOD set over GOLD TEST states
    across >= 6 families; only e9t/nsmc was reachable (997 states / 2991 questions).
  - Would have weakened todo 14's held-out evaluation.

This was not caught earlier because prior verification checked count floors and
blank states, but never asserted per-source coverage of the test split.

FIX (kojev/data_gold.py)
  - Added _shuffle_key(): deterministic SHA-256 ordering over the row payload
    salted with _SPLIT_SEED. Chosen over random.Random(0).shuffle because the
    latter trips Ruff S311 and is not guaranteed stable across Python releases;
    a seeded digest is reproducible and runtime-independent. No lint suppression.
  - Added _source_split_rows(): pools every configured upstream split for a
    source, orders by _shuffle_key, then carves disjoint per-source slices
    test<=1000, val<=500, train<=8000.
  - build_gold() now iterates those carved splits, so every source contributes
    to train, val, and test.

      no row (disjointness).
