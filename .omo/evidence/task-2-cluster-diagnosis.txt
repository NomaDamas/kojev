ROOT CAUSE
  /data2 is NFS with healthy sequential throughput but pathological small-file
  metadata cost. Python environments are tens of thousands of small files, so
  ANY per-job environment construction is fundamentally too slow here. The
  network was never the real problem.

CORRECTION 1 - shared warm package cache
  Both templates defaulted UV_CACHE_DIR to /data2/jeffrey/kojev/runs/uv-cache-${SLURM_JOB_ID}.
  sbatch does not propagate the submitting shell's UV_CACHE_DIR, so every job
  ignored any warm cache and re-downloaded the multi-GB CUDA wheel set.
  Now: UV_CACHE_DIR defaults to the shared /data2/jeffrey/kojev/uv-cache.
  Verified in job 13620: "Resolved 92 packages in 1ms" with ZERO Downloading lines.

CORRECTION 2 - skip dev dependencies on the cluster
  `uv sync` installs the dev group by default. basedpyright ships ~20k tiny
  typeshed stub files and drags in nodejs-wheel-binaries; unpacking those over
  NFS dominated wall clock for zero runtime benefit. The cluster trains, it does
  not lint.
  Now: `uv sync --no-dev`.
  Verified: package downloads dropped from 29 to 1 (torch only).

CORRECTION 3 - hardlink instead of copy
  UV_LINK_MODE=copy duplicated torch (~2GB, ~10k files) into every job venv.
  Cache and venv share the /data2 mount, so hardlinking is correct and removing
  a job venv only decrements link counts.
  Now: UV_LINK_MODE=hardlink.

CORRECTION 4 - prebuilt shared venv (addresses 13620)
  Even hardlinking ~10k torch files is metadata-bound and exceeded the 30-minute
  smoke limit. Jobs must not build environments at all.
  Now: templates prefer /data2/jeffrey/kojev/venv-shared when it exists,
  exporting UV_PROJECT_ENVIRONMENT/VIRTUAL_ENV/PATH at it, and fall back to a
  per-job `uv sync --no-dev` only when it is absent. Jobs invoke
  `uv run --no-sync` so they can never mutate the shared environment - which
  also makes the original 13597 .venv race impossible by construction.
  Promotion is by SYMLINK (venv-shared -> runs/venv-prewarm2) rather than a
  rename, so the venv's baked absolute paths stay valid.

SELF-INFLICTED INCIDENTS (recorded honestly)
  1. A broad `rm -rf /data2/jeffrey/kojev/uv-cache/.tmp*` was left running for
     roughly 90 minutes. The shell froze the glob into an explicit 52-directory
     list at launch, and the rebuilt `uv sync` then created a staging directory
     already on that list, so the rm deleted new work as fast as uv wrote it.
     Detected by measuring file count twice: 27,424 -> 27,240, a NEGATIVE delta.
     A build whose staging shrinks is not slow, it is losing a race.
     Lesson: never point a broad recursive delete at a directory an active build
     is using.
  2. Seven concurrent ssh monitors, several on 20-second intervals, plus manual
     checks, contributed to gpu01 refusing ssh connections entirely.
     Lesson: monitor intervals must be sized to the remote host's tolerance, or
     the monitoring denies the visibility it exists to provide.
